# Настройка админ-панели

Адреса после публикации:

- `/admin-login/` — вход;
- `/admin/` — заявки и календарь.

## 1. SQL

Если текущая база уже работала в функциональном Supabase-проекте и админка уже была настроена, новый SQL выполнять не нужно.

`ADMIN_SETUP.sql` оставлен как опциональный setup для свежей базы или случая, когда не хватает доступа Supabase Auth к админке. В таком случае откройте Supabase → `SQL Editor`, вставьте содержимое файла `ADMIN_SETUP.sql` и нажмите `Run`.

Скрипт:

- добавляет колонку `services`, не удаляя существующие данные;
- разрешает администратору читать и изменять заявки;
- не открывает публичную запись в `bookings`, потому что заявки создаёт серверный `/api/booking`;
- разрешает административный доступ любому пользователю с действующей сессией Supabase Auth.

## 2. Создать владельца

Откройте Supabase → `Authentication` → `Users` → `Add user` → `Create new user`.

Укажите:

```text
Email: email владельца или сотрудника
Password: задайте временный сложный пароль
Auto Confirm User: включено
```

Пароль нельзя записывать в HTML или JavaScript. После первого входа сохраните его в менеджере паролей.

Если самостоятельная регистрация на проекте не нужна, в настройках Supabase Auth отключите регистрацию новых пользователей.

## 3. Переменные Vercel

Убедитесь, что в `Project Settings` → `Environment Variables` сохранены:

```text
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
TELEGRAM_WEBHOOK_SECRET
```

После изменения переменных запустите новый deploy.

Настройка inline-кнопок Telegram и регистрация webhook описаны в `TELEGRAM_MANAGEMENT_SETUP.md`.

## 4. Проверка

1. Откройте `/admin-login/`.
2. Войдите под любым подтверждённым пользователем Supabase Authentication.
3. Убедитесь, что открывается таблица заявок.
4. Подтвердите тестовую заявку.
5. Проверьте, что её статус стал `confirmed`, а даты появились занятыми в календаре админки и на гостевом сайте.
6. Отмените тестовую заявку и проверьте освобождение дат.
7. Измените услуги или комментарий и обновите страницу.
8. Нажмите `Выйти` и убедитесь, что `/admin/` снова требует вход.

## Безопасность

Publishable/anon key является публичным по назначению. Защиту данных обеспечивает RLS.

Никогда не добавляйте `service_role` key или пароль администратора в файлы сайта, GitHub и клиентский JavaScript.

Все пользователи, созданные в Supabase Authentication, получают одинаковый административный доступ. Не создавайте учётные записи для посторонних лиц и отключите публичную регистрацию пользователей.
